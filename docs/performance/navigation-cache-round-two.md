# ETB キャッシュ・遷移高速化（第2段階 / 2026-11-13）

この変更は #560 の Router Cache（dynamic/static とも 30秒）を維持し、期限切れ時の通信・プリフェッチ過多・書き込み時の大域無効化を減らす。

## 変更内容

1. **Auth**: `proxy.ts` の `getUser()` を Supabase SSR 推奨の `getClaims()` に変更。JWT署名方式が非対称なら署名検証はローカルで実行される（最初のJWKS取得や有効期限更新を除く）。サーバーの管理操作と非公開ルームの認可は引き続き `getUser()` で検証。
2. **ルーム表示・編集**: 公開/限定公開のルーム詳細では、署名検証済み `getClaims()` を所有者UIの表示判定にのみ使用。これは認可権限ではなく、実際の編集操作や非公開ルーム表示では検証済み `getUser()` を使用する。編集画面は以前の「link→id→room」の2クエリを単一の所有者スコープ付きクエリに削減し、metadataとpage間はReact `cache()` で重複取得を回避。
3. **Prefetch**: 一覧の先頭4件の公開ルームのみ `prefetch=true`。残りの公開ルームはホバー/フォーカス時に先読みし、最初から全ルームを読み込まない。カード内の再生・編集アイコンリンクによる別プリフェッチも抑制。
4. **無効化**: `revalidatePath('/', 'layout')` を廃止。作成/更新/削除は `/`, `/mine`, `/saved` とルーム関連の動的 `page` パスを無効化、保存トグルは一覧3画面だけを対象とする。DB成功時のみ呼び出し、公開ルームのプロセス内2分キャッシュも従来通り世代付きで無効化。単語更新/URL変更時は旧URLの再訪問にも対応するため、動的パターンでルーム系を広く対象とする。

## 限界と安全性

- Next.js 16ではServer Actions内の `revalidatePath()` 自体が訪問済みのRouter Cacheを広く更新する挙動がある。今回の変更は**サーバー側の再検証対象の限定**であり、ブラウザキャッシュをパス単位に完全維持する保証はない。
- `getClaims()` はJWT署名が対称鍵の場合、Authへのネットワーク検証にフォールバックし得る。失効済みアクセストークンのサーバー側での厳密な取り消し検証が必要な更新・非公開操作では引き続き `getUser()` を使用。
- 公開/限定公開のページは誰でも読めるデータのみを表示する。クライアント表示の「所有者」判定を機密情報アクセスの根拠にしない。
- 別ブラウザ、別インスタンス、MCPでの更新は即時反映されない可能性がある。公開一覧の2分TTL（DB障害時のstale fallback最大12分）はそのまま。
- `edit_version` 楽観的排他制御と非公開パスワード検証は維持。
- 再訪問用Router Cacheは依然30秒。先頭4件のプリフェッチ以外で初回遷移時間が伸びる場合があるため、通信量とクリック待機時間のトレードオフを計測する。
