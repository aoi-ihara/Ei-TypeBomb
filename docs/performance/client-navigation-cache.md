# クライアントナビゲーションキャッシュ

## 原因と方針

- RoomCard は Link と router.push の両方で同じ遷移を起動していた。Link のみに統一し、PostHog capture は維持。進捗開始は onNavigate なので修飾キーで別タブを開いたときには開始しない。
- React cache は metadata/page 間のリクエスト内重複排除。ブラウザの再訪問キャッシュではないため維持する。
- 公開一覧取得を認証と同時に開始。所有・保存情報の取得は検証済みユーザーID確定後に限る。一覧データ関数自体も React cache でリクエスト内重複排除する。
- Cookie を読む一覧・詳細は動的RSC。Router Cache の dynamic の既定値は0秒。公開カードに prefetch=true を指定して完全プリフェッチを有効化し、experimental.staleTimes を dynamic/static とも30秒とする。設定は全ルートに適用される。SSRを維持し、新規ライブラリは導入しない。
- proxy は全遷移で getUser、ページ側も getUser で検証するため、ネットワークが必要な遷移には認証待ちが残る。認証を省略する変更は行わない。通常の往復で router.refresh は呼ばれていない。

仕様: https://nextjs.org/docs/app/api-reference/config/next-config-js/staleTimes
仕様: https://nextjs.org/docs/app/api-reference/components/link#prefetch
実装環境: インストール済み Next 16.4.6（package.json は ^16.3.0）。同梱 dist/docs でも確認した。staleTimes は実験的API。

## 有効期限と無効化

- Router Cache: タブ内のメモリにRSCを再利用。30秒は通常のリンク再訪問/プリフェッチの有効期間。リロードで破棄。戻る・進むの履歴再利用には別の規則があり、30秒で全履歴が消えるわけではない。
- 作成・編集（公開範囲、パスワード、リンク変更を含む）・削除がDBで成功してから revalidatePath('/', 'layout')。旧リンクや複数一覧を含め呼び出し元ブラウザのキャッシュを無効化。保存トグル成功時も無効化。失敗・競合では無効化しない。
- 既存の公開一覧プロセスキャッシュは2分、障害時はさらに10分の stale fallback。書き込み成功時に同一プロセスを破棄し、無効化前の取得が後からキャッシュを再作成しないよう世代で防ぐ。
- ログイン・ログアウトは既存Server ActionのCookie更新でNextのRouter Cacheが無効化される。認証コールバックはドキュメント遷移。ユーザー別情報を共有キャッシュに追加しない。private詳細の認可・パスワードCookie検査は既存のサーバー処理を維持する。
- 編集は既存の edit_version 条件付き更新を維持。古い表示データから保存しても無条件上書きせずconflictになる。
- 別ブラウザ/別プロセス/MCP経由の変更を即時配信する仕組みはない。公開一覧の既存TTL、ブラウザの短期キャッシュや履歴には古い表示が残り得る。表示キャッシュをゲーム参加・編集の認可根拠にはしない。

## 検証（2026-11-13）

ローカル本番ビルド、Chromium/Playwright、未ログイン、実データの読み取り。数値は1回の観測で、Playwrightのクリック処理とURL切替待ちを含み、描画完了や本番ユーザーの体感値ではない。

| 操作 | URL切替まで | 遷移先RSC | 判定 |
| --- | ---: | ---: | --- |
| おすすめ→apple-event（プリフェッチ後） | 43ms | 0 | キャッシュ再利用と推定 |
| 詳細→おすすめ | 45ms | 0 | 同上 |
| おすすめ→同じ詳細 | 47ms | 0 | 同上 |
| 詳細→おすすめ | 41ms | 0 | 同上 |
| おすすめ→別の公開詳細 | 49ms | 0 | 同上 |
| 詳細→おすすめ | 45ms | 0 | 同上 |

公開詳細の事前RSC要求を観測。初回詳細遷移時には /mine、/saved の背景プリフェッチ要求が発生したが、遷移先詳細の要求はなかった。各遷移250ms後、progressbarは0件。事前取得の負荷はゼロではなく、初回アクセスを高速化したという数値ではない。

成功: Next本番ビルド（ビルド組み込み import/kana/bot/editor テストを含む）、TypeScript、room-list、account、playground関連テスト。変更箇所ESLintはエラー0、RoomCardの既存未使用isOwner警告1件。全体ESLintは既存test/account-auth.test.cjsとtest/mcp-etb-auth.test.cjsのrequire禁止10エラー、その他11警告。

未検証: テストアカウント/専用書き込みデータがないため、編集保存・ログイン/ログアウト/アカウント切替・非公開の解除・削除/公開範囲変更のブラウザ操作。認可と競合制御はコード確認および既存テストのみで、操作成功を主張しない。オンライン/オフラインの実サーバー接続プレイ、PostHog配信の本番確認も未実施（自動ブラウザではPostHogがbotイベントを抑制）。

### 変更前との比較

同一HEADの変更前ソースを /tmp に展開し、同じ環境変数・Nextバージョン・ブラウザ・実データで計測。依存シンボリックリンクがTurbopackのroot制約に抵触したため変更前だけwebpackでビルドした。この差と単回計測のため時間の改善率は一般化しない。

| 操作 | 変更前ms / 対象RSC数 | 変更後ms / 対象RSC数 |
| --- | --- | --- |
| 初回の公開詳細（一覧表示後1.5秒待機） | 250 / 2 | 43 / 0 |
| おすすめへ戻るリンク | 59 / 1 | 45 / 0 |
| 同じ公開詳細を再訪問 | 571 / 2 | 47 / 0 |
| おすすめへ戻るリンク | 49 / 1 | 41 / 0 |
| 別の公開詳細 | 235 / 2 | 49 / 0 |
| おすすめへ戻るリンク | 45 / 1 | 45 / 0 |

RSC数はクリックからURL切替後250msまでの対象パスの要求数。初回のドキュメント取得時間と、プリフェッチ未完了時のクリック時間は未計測。0件は要求観測に基づくキャッシュヒットの推定で、Next内部のヒットカウンターではない。背景プリフェッチ全体では複数要求が残る。

変更後の戻る/進むも各1回実行し進捗バーが残らないことを確認。ただし履歴先に関する背景プリフェッチも発生したため、履歴操作全体が無通信という結論にはしていない。

実行ホストはNode 26.12.1（package.json指定22.xと異なる）。ビルド時にLINE Seed JPのフォールバック警告、ローカルブラウザでは未配置のVercel Analyticsスクリプト404あり。変更前webpackビルドには既存parseImportedWords exportの警告もあった。いずれも成功したビルド・ブラウザ操作結果とは分けて記録する。
